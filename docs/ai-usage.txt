[싸피] 잡도리 — AI 활용내역

1. 활용 AI 모델·API
- Google Gemini API (무료 등급, OpenAI 호환 엔드포인트)
  · gemini-3.5-flash-lite: 공고 전형 일정 추출, 합격·일정 안내 메일 판독
  · gemini-3.8-flash: 맞춤 공고 추천 이유, 일정 충돌 조정 문구 (혼잡·지연 시 12초 후 Flash-Lite로 자동 대체)
- 모든 LLM 출력은 Zod 스키마로 구조화 검증. 모델·공급자는 환경변수로 교체 가능(하드코딩 없음)

2. 서비스 안에서 AI가 하는 일 / 하지 않는 일
- AI: 공고 원문 → 전형 단계·날짜 종류(확정·범위·미정)·원문 근거 문장 추출 / 안내 메일 → 합격 여부·다음 전형 날짜·시각 / 추천 이유·조정 문구 작성
- 코드(규칙): 미정 일정 추정(점점선), 날짜 정리 규칙, 일정 충돌 판단, 조정 대상 선정, 추천 점수
- 사용자: 모든 일정 추가·확정·삭제는 사용자가 승인해야 반영 (AI는 제안만)

3. 오류·불확실성 대응
- 모든 날짜에 원문 근거 문장 표시, 원문에 없는 근거는 '근거 확인 필요' 표시
- 확정=실선 / 범위 추정=점선 / 규칙 추정=점점선으로 신뢰도 구분
- 안내 메일은 이름·이메일·전화번호를 가린 뒤 전송, 원문은 저장하지 않음
- 조정 문구에 다른 기업명이 들어가면 기본 문구로 대체, 키가 없거나 호출 실패 시 기본 문구로 동작
- 같은 공고는 원문 해시로 1회만 분석(공유 캐시) → 비용·호출 수 절감

4. 실측 (2026-11-20, 가상 평가셋)
- 전형 추출 141/141 단계(100%) — 개선 전 68.8%, 날짜 규칙을 코드·프롬프트에 반영 후 재측정
- 비정형 공고 10건(서술형·표·영문·상대 날짜): AI 41/41(100%) vs 규칙 추출 0/41(0%) — 정형 공고는 규칙으로도 풀리지만 실제 공고 형식은 AI가 필요
- 안내 메일 판독 20/20(100%) — 개선 전 95%
- 일정 충돌 시나리오 10/10, 오탐 0 / 공고 1건 분석 평균 1.6초
- 평가셋을 보고 보완했으므로 실제 공고에서는 낮을 수 있어, 사용자 수정 내역을 평가셋에 추가해 계속 보완

5. 외부 데이터
- 공공데이터포털 잡알리오 공공기관 채용정보, 한국산업인력공단 국가자격 시험일정 (연동 예정, 현재 시연은 가상 데이터)
- 평가·시연 데이터: 팀이 만든 가상 공고 30건·안내 메일 20건·충돌 시나리오 10건. 실존 개인정보 없음, 실제 기업명은 '시연용 가상' 표시
- 민간 채용 플랫폼은 크롤링하지 않고, 사용자가 연 공고 페이지만 크롬 확장으로 읽음
